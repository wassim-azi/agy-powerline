# Security review

**Date:** 25 October 2026 · **Code reviewed:** the code as of 25 October 2026, released with this review as 1.8.0 (`v1.8.0`) · **Next review:** by October 2027, or before a release that adds a process, a file write or a network call.

This is an in-house review of agy-powerline against the security requirements and trust boundaries in the [assurance case](SECURITY.md#assurance-case). It reads the code where those boundaries are crossed, checks that each claim in [SECURITY.md](SECURITY.md) holds, and records what it found.

## Method

The code was read where untrusted input comes in or where the software acts on the machine: running commands, starting `git`, writing and deleting files, printing text, and publishing releases. Each area below names what was checked. The test suites that cover those areas (`security`, `robustness`, `install safety`, `fuzz`, `git`, `exec cache`, `problem log`) were run with ESLint, and CodeQL scanned the reviewed commit in CI. The workflows were read by hand; zizmor and actionlint check them in CI whenever a workflow file changes.

## Areas reviewed

| Area                                         | What was checked                                                                                                                                                                                                                                                                                                                                                                                                                          | Result           |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Who can make the bar run a command           | `isTrustedInstallDir()` compares real paths (links resolved, case-insensitive on Windows) with `~/.agy-powerline` and `AGY_POWERLINE_HOME` only; `renderStatusline` runs `exec` widgets only with `{ exec: "run" }`; every CLI preview shows `[cmd]`.                                                                                                                                                                                     | No issue         |
| Importing a config                           | `import` lists every `exec` command it would add, asks with a default of No, refuses without a terminal, and `--yes` alone doesn't accept commands.                                                                                                                                                                                                                                                                                       | No issue         |
| Running `exec` commands                      | The user's command goes through the shell on purpose; timeout capped at 5 s; stdin empty or the payload without email and session IDs; output stripped of control sequences and capped at 80 characters; cache files created owner-only with `wx`.                                                                                                                                                                                        | Findings 1 and 2 |
| Starting `git` in a repository you open      | Every call is `execFileSync` with an argument array and a timeout (150 ms, 300 ms); branch names are checked before use (no leading `-`, no `..`, no `@{`, no control characters); `status` and `diff` run with `core.fsmonitor=false`, no external diff or textconv, submodules ignored, and not at all when the repo's own config names filters, diff drivers, includes or fsmonitor. `rev-list --count` starts no program from config. | No issue         |
| Printing text that isn't ours                | `stripControl` removes OSC (titles, clipboard, hyperlinks), CSI, other escapes, C0 and C1 controls, line and paragraph separators and bidi overrides; `renderStatusline` cleans the whole session object before any layout prints it.                                                                                                                                                                                                     | Finding 3        |
| Writing agy's `settings.json` and the config | A file that doesn't parse is never overwritten; a backup is kept; writes are atomic; a symlinked file stays a link; only the `statusLine` key changes.                                                                                                                                                                                                                                                                                    | No issue         |
| Deleting files                               | `uninstall --delete` removes only the names in `INSTALLED_FILES`, then folders only if empty; no recursive delete on a path from config or the environment.                                                                                                                                                                                                                                                                               | No issue         |
| The problem log and `report`                 | Entries are built from an allowlist; messages have paths, home folder, user and host names, emails, URLs, IPs and token-like strings removed; files are `0600` on macOS and Linux.                                                                                                                                                                                                                                                        | No issue         |
| The statusline under bad input               | stdin is read with a deadline and closed; a missing or malformed payload exits 0 with a short fixed marker at most; errors go to the local log, never as a stack trace in the bar.                                                                                                                                                                                                                                                        | No issue         |
| Supply chain                                 | No runtime dependencies; workflows start from `permissions: {}`; actions pinned to commits; `pull_request_target` used only by the labeler, welcome and thanks workflows, which never check out the pull request's code; event data reaches scripts through `env`; releases need a tag on `main` and the maintainer's approval, and carry signed provenance.                                                                              | No issue         |
| Website                                      | Static pages, a Content Security Policy in each page. Only the website uses Google Analytics to count visits; the tool (statusline and CLI) has no analytics.                                                                                                                                                                                                                                                                             | Finding 4        |

## Findings

| #   | Severity      | Finding                                                                                                                                                                                                                                                                                                                                                                                                           | Status                                                                               |
| --- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 1   | Low           | When an `exec` command times out, Node stops the shell it started, but on Windows a program that shell started can keep running (seen with `ping`). It runs as the user, with the user's own command, so no boundary is crossed; it costs resources until it ends.                                                                                                                                                | Open, planned in [ROADMAP.md](ROADMAP.md) ("`exec` timeouts end the whole command")  |
| 2   | Informational | `getCacheFilePath()` falls back to a per-user file name in the system temp folder when there is no config file. On a Linux machine shared with other accounts, that name can be guessed and the file pre-created. The runtime never reaches the fallback, since `exec` widgets only run from a config file in the install dir, but the code comment claimed the name alone prevented this.                        | Comment corrected in this review                                                     |
| 3   | Informational | `sanitizeDeep` stops descending after 8 levels of nesting. The session object it cleans is far shallower, so every string a layout prints is cleaned today; a deeper session object in the future would need the limit raised.                                                                                                                                                                                    | Accepted                                                                             |
| 4   | Low           | agy-powerline.com is served by GitHub Pages, which sends no HTTP security headers (HSTS, `Content-Security-Policy`, `X-Content-Type-Options`, `frame-ancestors`). The pages set their CSP in a `<meta>` tag, which can't express `frame-ancestors`, so the site can be framed by another page. The site has no forms or accounts, and only Google Analytics sets cookies on the website, which limits the impact. | Accepted: the site stays on GitHub Pages alone, with no third-party proxy or service |

No finding allows a repository, a payload, command output or an imported file to run a command, change the user's settings or read their data.

## Process

Every change to `main` runs the full test suite on Linux, macOS and Windows, ESLint, CodeQL and, for workflow changes, zizmor and actionlint. The project has one maintainer, so the maintainer's own changes are not reviewed by a second person; [GOVERNANCE.md](GOVERNANCE.md) and [ROADMAP.md](ROADMAP.md) cover this.
